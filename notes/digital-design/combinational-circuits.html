Combinational Circuits

Introduction

A combinational circuit has no stored state: after propagation delay, its outputs depend only on its current inputs. An acyclic network of Boolean gates implements a Boolean function.

  • Analysis: derive expressions and a truth table from the circuit.
  • Design: derive and simplify expressions from a specification, then map them to gates.

Gate identities are in Boolean Algebra; SystemVerilog modeling rules are in RTL Design Guide.

Electrical Logic and CMOS

Bits are voltage ranges. A receiver accepts a low below VILV_{IL} and a high above VIHV_{IH}; a driver guarantees a low no higher than VOLV_{OL} and a high no lower than VOHV_{OH}. The noise margins are

NML=VIL−VOL,NMH=VOH−VIH.NM_L=V_{IL}-V_{OL},\qquad NM_H=V_{OH}-V_{IH}.

Positive margins tolerate bounded noise. Between input thresholds, the logical interpretation is unspecified. The static discipline requires valid, stable inputs to produce valid outputs after the propagation delay. Check voltage compatibility, load, and input slew when connecting gates.

In the CMOS switch model, nMOS conducts for a high gate voltage and pMOS for a low one. Complementary static CMOS uses an nMOS pull-down to ground and a dual pMOS pull-up to the supply:

Gate nMOS pull-down pMOS pull-up
inverter one transistor one transistor
NAND2 two in series two in parallel
NOR2 two in parallel two in series

For stable binary inputs, one network conducts and the other is off. Real gates still leak and draw switching current. More fanout adds capacitance; larger drivers reduce resistance but increase input load and area. Synthesis, Timing and Power connects these effects to delay and energy.

Multiplexer

Selects one input. The 2:1 mux computes y=sd0∨sd1y = \bar{s}\,d_0 \lor s\,d_1, written y = sel ? d1 : d0.

A 2k2^k:1 mux with constants on its data inputs realizes any kk-input truth table directly, exactly how an FPGA LUT works.

Shannon expansion halves the mux: expand about the select variables and put what remains on the data inputs. Start from the full truth table of 3-input majority:

Fixing a,ba, b collapses each pair of rows into a function of cc alone (constant 00, cc, cc, constant 11), and those residues become the 4:1 mux’s data inputs with {a,b}\{a, b\} on the selects:

Decoder

Turns an nn-bit code into one-hot of 2n2^n outputs. The 2:4 decoder drives the four minterms y0=aby_0 = \bar a\bar b, y1=aby_1 = \bar a b, y2=aby_2 = a\bar b, y3=aby_3 = ab, gated by an enable.

Because the outputs are the minterms, a decoder plus OR gates implements any set of functions of the same inputs: OR together the outputs for the rows where each function is 11 (a ROM is exactly this structure). A demultiplexer is a decoder with data on the enable: the data value is routed to output number sel, all other outputs stay 00.

Encoder

The inverse of a decoder: an active input drives its index onto the output. A priority encoder resolves multiple active inputs by reporting the highest index, with a valid flag distinguishing “index 0” from “no input”.

Tristate Buffers and Buses

A tristate buffer passes its input when enabled and presents high impedance (ZZ) when not. Tying several enabled-one-at-a-time tristates to one wire forms a shared bus. At most one driver should be enabled; no driver leaves the bus floating unless a pull resistor or bus keeper defines its level. Conflicting drivers cause contention.

Adders

A half adder sums two bits: s=a⊕bs = a \oplus b, cout=abc_{out} = ab.

A full adder adds a carry input, built from two half adders and an OR: s=a⊕b⊕cin,cout=ab∨cin(a⊕b) s = a \oplus b \oplus c_{in}, \qquad c_{out} = ab \lor c_{in}(a \oplus b)

Chaining nn full adders, each carry feeding the next, gives a ripple-carry adder. It is small but its delay is O(n)O(n) along the carry path.

Carry lookahead

The fix is to compute carries directly instead of waiting for the ripple. Bit ii generates a carry if both inputs are high and propagates an incoming carry if exactly one is: gi=aibi,pi=ai⊕bi,ci+1=gi∨pici. g_i = a_i b_i, \qquad p_i = a_i \oplus b_i, \qquad c_{i+1} = g_i \lor p_i c_i. Unrolling the recurrence expresses every carry in the ggs, pps, and c0c_0 alone, two AND/OR levels if arbitrary fan-in is available, excluding g,pg,p generation: c1=g0∨p0c0c2=g1∨p1g0∨p1p0c0c4=g3∨p3g2∨p3p2g1∨p3p2p1g0∨p3p2p1p0c0 \begin{aligned} c_1 &= g_0 \lor p_0 c_0 \\ c_2 &= g_1 \lor p_1 g_0 \lor p_1 p_0 c_0 \\ c_4 &= g_3 \lor p_3 g_2 \lor p_3 p_2 g_1 \lor p_3 p_2 p_1 g_0 \lor p_3 p_2 p_1 p_0\, c_0 \end{aligned} The sum stage reuses the propagate signal: si=pi⊕cis_i = p_i \oplus c_i.

The flat terms grow too wide past a few bits, so wide adders go hierarchical: a 4-bit block exports block generate and propagate, G=g3∨p3g2∨p3p2g1∨p3p2p1g0G = g_3 \lor p_3 g_2 \lor p_3 p_2 g_1 \lor p_3 p_2 p_1 g_0 and P=p3p2p1p0P = p_3 p_2 p_1 p_0, and a second-level lookahead computes the block carries. A related speedup, the carry-select adder, computes each upper block twice (for cin=0c_{in}=0 and 11) and muxes on the real carry.

Parallel-Prefix Adders

Carry lookahead generalizes to a prefix computation. Define a merge operator on (generate, propagate) pairs:

(G,P)•(G′,P′)=(G∨PG′,PP′)(G, P) \bullet (G', P') = (G \lor P\,G',\; P\,P')

“The combined span generates a carry if the upper part generates one, or propagates one the lower part generates.” The operator is associative, and the prefix (Gi:0,Pi:0)=(gi,pi)•⋯•(g0,p0)(G_{i:0},P_{i:0})=(g_i,p_i) \bullet \cdots \bullet (g_0,p_0) gives ci+1=Gi:0∨Pi:0c0c_{i+1}=G_{i:0}\lor P_{i:0}c_0, so computing all carries is a parallel prefix problem, the same one behind fast scans in parallel programming. Any prefix network is a valid adder, and the network’s shape sets the trade:

Network Stages Cells Character
Kogge-Stone log2n\log_2 n O(nlogn)O(n \log n) minimal depth, max wires: fast and hungry
Brent-Kung 2log2n−12\log_2 n - 1 ≈2n\approx 2n fewer cells and wires; greater depth
Sklansky log2n\log_2 n n2log2n\frac{n}{2}\log_2 n minimal depth, but high-fanout nodes need buffering

Hybrid prefix networks trade wiring, fanout, and depth. The sum remains si=pi⊕cis_i=p_i\oplus c_i.

Subtraction

Subtraction reuses an adder: a−b=a+b+1a - b = a + \bar{b} + 1 (two’s complement).

XOR each bit of bb with sub and use sub as the carry-in:

assign sum = a + (b ^ {W{sub}}) + sub;   // sub=0: a+b, sub=1: a-b

For signed operands, overflow is a mismatch between the carries into and out of the sign bit: ov=cN⊕cN−1ov = c_{N} \oplus c_{N-1}.

Comparator

Equality is a bitwise XNOR of the two operands ANDed together: eq=∏iai⊕bieq = \prod_i \overline{a_i \oplus b_i}. Magnitude (a<ba < b) is a subtractor whose borrow/sign output is examined, or a chain comparing from the most significant bit down. For unsigned operands the borrow alone decides; for signed operands the difference’s sign bit lies exactly when the subtraction overflows, so ltsigned=dN−1⊕ov,d=a−b. lt_{signed} = d_{N-1} \oplus ov, \qquad d = a - b.

Shifters

A shifter moves a word by a variable amount. Three flavors:

  • Logical (<<, >>): vacated bits fill with 00.
  • Arithmetic right (>>>): sign-fills only when the left operand is signed. It divides by 2k2^k, rounding toward negative infinity. Left shifts multiply by 2k2^k only when the result fits.
  • Rotate: bits shifted off one end reenter the other.

A barrel shifter handles any shift amount without iteration: ⌈log2N⌉\lceil\log_2 N\rceil stages of 2:1 muxes, stage ii shifting by 2i2^i when select bit sis_i is set. Any shift amount is a sum of powers of two, so the stages compose.

For N=8N=8, three select bits control shifts by 1, 2, and 4, giving a total shift of 0–7 positions.

ALU

An ALU bundles the arithmetic and logic operations behind a function-select input, producing a result and status flags: Z (result zero, the wide NOR of its bits), N (sign bit), C (carry out), V (signed overflow). It is the computational core of a datapath.

Multiplier

Unsigned multiplication sums shifted partial products; each row is the multiplicand ANDed with one multiplier bit:

a3a2a1a0×b3b2b1b0a3b0a2b0a1b0a0b0a3b1a2b1a1b1a0b1a3b2a2b2a1b2a0b2a3b3a2b3a1b3a0b3 \begin{array}{rrrrrrrr} {} & {} & {} & {} & a_3 & a_2 & a_1 & a_0 \\ {} & {} & {} & \times & b_3 & b_2 & b_1 & b_0 \\ \hline {} & {} & {} & {} & a_3b_0 & a_2b_0 & a_1b_0 & a_0b_0 \\ {} & {} & {} & a_3b_1 & a_2b_1 & a_1b_1 & a_0b_1 & {} \\ {} & {} & a_3b_2 & a_2b_2 & a_1b_2 & a_0b_2 & {} & {} \\ {} & a_3b_3 & a_2b_3 & a_1b_3 & a_0b_3 & {} & {} & {} \\ \end{array}

An array multiplier lays this out as a grid of AND gates and adders (O(n2)O(n^2) area, O(n)O(n) delay). Faster multipliers use carry-save addition: a full adder compresses three partial-product bits to a sum and a carry with no carry ripple, so a Wallace/Dadda tree reduces all rows to two in O(logn)O(\log n) levels, and a single fast adder produces the final product.

Signed Multiplication and Division

An NN-bit by NN-bit product needs up to 2N2N bits. Signed multiplication must account for the sign weights; Booth recoding replaces groups of multiplier bits with signed multiples of the multiplicand, reducing partial products. Truncating to NN bits keeps the low product modulo 2N2^N, losing overflow information.

A small sequential multiplier reuses a shift-and-add datapath over several cycles. A restoring divider repeatedly shifts the partial remainder, subtracts the divisor, and restores it when the subtraction is negative; each step determines a quotient bit. Faster dividers produce more bits per step or use reciprocal approximation. Divide-by-zero, signed overflow, and rounding are part of the arithmetic contract, not consequences to leave to the circuit.

Logic Arrays

Regular two-level structures implement sum-of-products directly: an AND plane forms product terms from the inputs and their complements, and an OR plane sums chosen products into each output. The families differ only in which plane is configurable:

Structure AND plane OR plane
ROM (read-only memory) fixed (full decoder: every minterm) programmable
PLA (programmable logic array) programmable programmable
PAL (programmable array logic) programmable fixed

A PAL trades the PLA’s flexibility (each output owns a fixed set of product terms) for speed and simpler programming; PLD is the umbrella term for all such programmable-logic devices, of which the PAL family was the commercial workhorse before FPGAs.

An FPGA generalizes this with lookup tables (LUTs): a kk-input LUT is a 2k2^k:1 mux fed by a 2k2^k-bit truth-table memory, realizing any kk-input function.

Propagation Delay

Propagation delay tpdt_{pd} bounds settling time; contamination delay tcdt_{cd} bounds the earliest output change. Unequal path delays can produce glitches. See Synthesis, Timing and Power for clock constraints.

Hazards

A hazard is a momentary wrong output (glitch) from unequal path delays, even when the logic is correct. A static-1 hazard is a brief 00 on an output that should stay 11 (static-0 the reverse) when a single input change crosses between two product terms. Take y=ab∨bcy = ab \lor \bar{b}c with a=c=1a = c = 1 and bb falling: the term abab turns off through one gate while bc\bar{b}c turns on through the inverter plus a gate, so for one inverter delay neither term holds the output up.

On the K-map the two groups touch but do not overlap; no single group covers both cells the transition moves between:

a∖bca \backslash bc 00 01 11 10
0 0 1 0 0
1 0 1 1 1

The fix is the redundant consensus term acac bridging the adjacent groups: y=ab∨bc∨acy = ab \lor \bar{b}c \lor ac stays 11 through the transition because acac does not depend on bb at all. Dynamic hazards (multiple transitions on one change) arise in multi-level logic with reconverging paths. Glitches do not corrupt synchronous capture when setup and hold are met, but still consume power. They matter directly on clocks, asynchronous controls, and latch enables.
