Sequential Circuits

Introduction

A sequential circuit’s outputs depend on the current inputs and on stored state, a summary of the input history (a TV tuner must remember the current channel to act on “channel up”). Structurally it is combinational logic plus memory elements in a feedback loop: state feeds the logic, the logic computes the next state.

Two disciplines exist:

  • Synchronous: state lives in flip-flops that all update on the edge of a shared clock. Between edges, signals may glitch and settle freely; only the settled value at the next edge matters. The slowest register-to-register path bounds the clock frequency.
  • Asynchronous: no clock, state changes ride directly on input changes through gate feedback and delays. Response is immediate, but correctness depends on races: when two signals change close together, which one wins a feedback loop can decide the next state, so behavior can hinge on physical delays.

Race conditions and hazard sensitivity make asynchronous design hard, so virtually all practical design is synchronous, with asynchronous techniques reserved for interfaces between clock domains or reset circuitry. The rest of this note is the synchronous toolkit. Latches and flip-flops themselves are small asynchronous circuits, designed once, characterized carefully, and reused as black boxes.

Latches

A bistable holds one bit using feedback. Cross-coupling two NOR gates gives an SR latch: \(S\) sets \(Q=1\), \(R\) resets \(Q=0\), both low holds, both high is illegal (\(Q\) and \(\bar{Q}\) both driven low, and releasing \(S\) and \(R\) together races).

\(S\) \(R\) \(Q^+\)
0 0 \(Q\) hold
0 1 0 reset
1 0 1 set
1 1 – illegal

Its characteristic equation (next state as a function of inputs and present state, assuming \(SR \ne 11\)): \(Q^+ = S \lor \bar{R}Q\). Gating \(S\) and \(R\) with an enable gives the clocked SR latch, active only while the enable is high.

A D latch removes the illegal state by deriving \(S = D\), \(R = \bar{D}\) behind the enable, so \(Q^+ = D\). It is level-sensitive: while EN is high it is transparent (\(Q\) follows \(D\)); while low it holds. Transparency makes latches hard to time, so synchronous RTL avoids inferring them.

Flip-Flops

A D flip-flop is edge-triggered: it samples \(D\) only on the rising clock edge and holds for the rest of the cycle. The classic construction is master-slave: two D latches on opposite clock phases. While the clock is low the master is transparent and the slave holds; on the rising edge the master closes, freezing the value the slave then presents. No moment exists when input can flow straight through, which is what edge triggering means. The triangle on the clock pin marks edge sensitivity. It is the standard state element.

Variants derive from it, each defined by its characteristic equation:

Type Characteristic Behavior
D \(Q^+ = D\) load every edge
T \(Q^+ = Q \oplus T\) toggle when \(T=1\)
JK \(Q^+ = J\bar{Q} \lor \bar{K}Q\) set on \(J\), reset on \(K\), toggle on both

Read in reverse, the excitation table gives the inputs forcing a desired \(Q \to Q^+\) transition, the classical recipe for designing FSM next-state logic with T or JK flops (a D flop’s excitation is trivially \(D = Q^+\), one reason it won). In modern synchronous design everything is a D flop; T and JK survive as exercises and inside counters.

Each flip-flop imposes timing constraints around the edge (\(t_{setup}\), \(t_{hold}\), clock-to-\(Q\)), and together with the logic delay between flops they set the clock period. The full timing story, from the setup and hold equations to skew, metastability, and static timing analysis, is the subject of [[Synthesis, Timing and Power]].

Describing Sequential Logic

Model edge-triggered state with always_ff and the nonblocking assignment (<=). Combinational blocks use blocking =; sequential blocks use <=. Mixing them is the main source of simulation versus synthesis mismatch.

always_ff @(posedge clk)
  if (rst)     q <= '0;    // synchronous reset
  else if (en) q <= d;     // load only when enabled

Registers

A register is \(n\) flip-flops on a shared clock storing an \(n\)-bit word, usually with an enable (conditional load) and a reset (force to a known value). A slash with a number marks a bus width.

Shift Registers

Connecting each flip-flop’s output to the next input shifts the word one position per clock. Used for serial-to-parallel conversion, delays, and LFSR sequence generators.

always_ff @(posedge clk) q <= {q[2:0], in};   // shift left, in at LSB

Counters

Feeding a register through an incrementer makes a binary counter. Variants add load, enable, up/down direction, and a terminal-count output. Common shapes:

  • Mod-N: reset to 0 on reaching \(N-1\); a BCD digit is mod-10. Cascade digits on the terminal count.
  • Divide-by-\(2^k\): bit \(k-1\) of a free-running counter toggles at \(f_{clk}/2^k\), a square wave.
  • Ripple counter: each flop clocks off the previous \(Q\), tiny but asynchronous; the count settles bit by bit, so synchronous counters are preferred.
  • Ring / Johnson: a ring counter circulates a single one (\(n\) states, one-hot, decode-free); a Johnson counter feeds back the inverted output for \(2n\) states from \(n\) bits.

An LFSR (linear feedback shift register) counts through a pseudo-random sequence: shift, with the input the XOR of taps given by a generator polynomial over \(GF(2)\). A maximal polynomial such as \(x^4 + x^3 + 1\) cycles through all \(2^4 - 1\) nonzero states:

always_ff @(posedge clk) lfsr <= {lfsr[2:0], lfsr[3] ^ lfsr[2]};

Reading taps off the polynomial: the register has as many bits as the degree (here 4), and each middle term \(x^k\) marks a tap after stage \(k\), so \(x^4 + x^3 + 1\) means “feed back bit 3 XOR bit 2” in the 0-indexed code above. A bigger example, CRC-CCITT’s generator \(x^{16} + x^{12} + x^5 + 1\), becomes a 16-bit shift register with

always_ff @(posedge clk) crc <= {crc[14:0], crc[15] ^ crc[11] ^ crc[4]};

The next-state logic is a couple of XORs regardless of width, so LFSRs make the cheapest “counters” when the count order is irrelevant, and the same structure computes CRCs, scramblers, and test-pattern generators.

Memory

A register file is a small multi-port array: combinational (asynchronous and instantaneous) read ports and a clocked (next cycle reflecting) write port. It backs a CPU’s architectural registers.

logic [31:0] rf [0:31];
assign rd1 = rf[ra1];
always_ff @(posedge clk) if (we) rf[wa] <= wd;

Larger storage uses RAM, typically a single port with a registered read so it maps to a dense block-RAM primitive.

logic [W-1:0] mem [0:DEPTH-1];
always_ff @(posedge clk) begin
  if (we) mem[addr] <= din;
  dout <= mem[addr];          // registered read
end

FIFO

A FIFO buffers data between producer and consumer using a circular buffer with write and read pointers. full and empty flags come from comparing the pointers; a wrap bit distinguishes the two equal-pointer cases. A dual-clock FIFO with Gray-coded pointers safely crosses clock domains.

Arbiter

An arbiter grants a shared resource to one of several requesters, one grant per cycle. A fixed-priority arbiter always favors the lowest index (a priority encoder over the request vector); a round-robin arbiter rotates priority after each grant for fairness.

Pipelining

Inserting registers to split a long combinational path into stages raises throughput to one result per clock at the cost of latency; the slowest stage sets the period. The worked example, the forwarding pitfall, and the loop-carried-dependency limit are in [[Synthesis, Timing and Power]]; the technique applied to a whole processor is the [[Simple Instruction Pipeline]].

Finite State Machines

An FSM is sequential logic with named states. It has combinational next-state logic, a state register, and combinational output logic.

  • Moore: outputs depend only on the state. Glitch-free, may need extra states.
  • Mealy: outputs depend on state and inputs. Fewer states, outputs can change mid-cycle.

The design procedure:

  1. State diagram from the spec: circles are states, labelled arrows are transitions.
  2. State table: rows of (present state, input) → (next state, output). Merge states with identical rows (state minimization).
  3. Encoding: assign each state a binary code.
  4. Equations: derive next-state and output logic from the table (in RTL, write the case and let synthesis minimize).

The example below is a Mealy “101” sequence detector; the 1/det arc asserts the output the cycle the pattern completes.

Code it in the three-block style: one always_ff for the state register, one always_comb for next state, one for outputs.

typedef enum logic [1:0] { S0, S1, S2 } state_t;
state_t state, next;

always_ff @(posedge clk)
  state <= rst ? S0 : next;

always_comb begin
  next = state;
  unique case (state)
    S0: if (in) next = S1;
    S1: next = in ? S1 : S2;
    S2: next = in ? S1 : S0;
  endcase
end

assign det = (state == S2) && in;   // Mealy output

A Moore version of the same detector needs a fourth state, “just saw 101”, whose mere occupancy asserts det, and its output arrives one cycle later since the pattern must first be registered into that state. That is the general trade: Mealy reacts in the same cycle with fewer states; Moore is a clean registered output, one cycle behind.

State encoding trades area against speed: binary uses \(\lceil\log_2 N\rceil\) flip-flops; one-hot uses \(N\) flip-flops with simple, fast next-state logic (favored on FPGAs); Gray encoding changes one bit per step to cut switching and crossing hazards. Codes left unused are unreachable in theory but reachable after an upset, so safe designs give unique case a default routing unknown states back to reset.
