Caches and Virtual Memory

Processor speed grew ~50%/year for decades while DRAM latency improved a few percent: the memory wall. The memory hierarchy hides it by exploiting locality: temporal (recently used data is used again) and spatial (nearby data is used soon). Caches make average access time approach SRAM speed at DRAM capacity; virtual memory extends the same illusion to protection and disk. Both matter more to real performance than anything in Simple Instruction Pipeline.

Cache Anatomy

Data moves in lines (blocks) of 32-128 B (64 B standard): fetching a whole line amortizes DRAM access and prefetches spatially. A cache holds a subset of lines plus bookkeeping: a valid bit and a tag identifying which memory line occupies the slot.

The address splits into three fields (line size 2b2^b, number of sets 2s2^s):

address=[tag⏟rest|index⏟sbits|offset⏟bbits]\text{address} = [\ \underbrace{\text{tag}}_{\text{rest}}\ |\ \underbrace{\text{index}}_{s\ \text{bits}}\ |\ \underbrace{\text{offset}}_{b\ \text{bits}}\ ]

The index selects a set, the stored tag is compared against the address tag, and on a hit the offset selects the word. Placement policies differ only in how many slots a line may occupy:

Organization Line can live in Cost Conflict misses
direct-mapped exactly 1 slot 1 comparator worst
NN-way set-associative NN slots of one set NN comparators + way mux low for N≥4N \ge 4
fully associative anywhere comparator per line (CAM) none

Worked example: 32 KiB, 8-way, 64 B lines, 48-bit addresses. Sets =32768/(8×64)=64= 32768/(8 \times 64) = 64, so offset b=6b=6, index s=6s=6, tag =48−12=36= 48-12 = 36 bits. Note the index+offset fit in 12 bits, exactly a 4 KiB page; this is deliberate (VIPT, below).

With tL1=2t_{L1}=2, mL1=5%m_{L1}=5\%, tL2=15t_{L2}=15, mL2=20%m_{L2}=20\%, tmem=300t_{mem}=300: AMAT=2+0.05(15+0.2×300)=5.75AMAT = 2 + 0.05(15 + 0.2 \times 300) = 5.75 cycles. Distinguish local miss rate (misses/accesses to that level) from global (misses/all accesses); L2’s local rate looks bad because L1 already filtered the easy hits.

The 3 Cs classify misses by what would have prevented them:

Miss class Cause Fix
compulsory first touch ever larger lines, prefetching
capacity working set > cache size bigger cache, blocking in software
conflict too many lines map to one set more associativity, victim cache

Line size is a trade, not a free win: bigger lines cut compulsory misses while spatial locality lasts, then waste bandwidth and evict useful data (fewer lines for the same capacity).

Policies

Replacement (which way to evict): LRU is ideal for small associativity; 8-way and above use tree pseudo-LRU (N−1N-1 bits per set, one bit per binary decision) or random. The LLC often uses smarter policies (RRIP) resistant to scans.

Writes:

  • Write-through: every store goes to the next level too. Simple, coherent, but needs a write buffer to hide latency and burns bandwidth.
  • Write-back: stores dirty the line; memory is updated only on eviction (dirty bit). Standard everywhere beyond tiny L1s; the eviction write-back traffic reappears in Multicore Cache Coherence as the Owned state problem.
  • Write-allocate (fetch line on store miss, standard with write-back) vs no-allocate (send the store on, standard with write-through).

Latency-hiding: non-blocking caches keep servicing hits under outstanding misses, tracking them in MSHRs (miss status holding registers), which is what lets out-of-order cores overlap misses (memory-level parallelism). Victim caches (small fully associative side buffer of recent evictions) mop up conflict misses. Prefetchers (next-line, stride, stream) fetch ahead of demand; accurate ones hide most compulsory/capacity latency, inaccurate ones pollute. Critical-word-first returns the needed word of a line before the rest.

Software helps: loop blocking restructures matrix code so the working tile fits in cache, turning capacity misses into hits.

Virtual Memory

Virtual memory gives every process its own address space, mapped to physical frames by the OS:

  • Protection/isolation: a process cannot name another’s memory; per-page permissions (R/W/X, user/supervisor).
  • Relocation: all programs link at the same addresses; sharing (libraries, copy-on-write fork).
  • Demand paging: run programs bigger than DRAM, faulting pages in from disk.

Memory is divided into pages (4 KiB standard; 2 MiB/1 GiB huge pages). The page table, maintained by the OS and walked by hardware, maps virtual page number (VPN) to physical page number (PPN). Each PTE holds PPN plus valid, permissions, accessed and dirty bits.

A flat table is infeasible (RV64 Sv39: 2272^{27} entries per process), so tables are hierarchical, and sparse address spaces allocate only the paths in use:

Each VPN slice indexes one level; a leaf PTE at an upper level maps a huge page. A miss at any level with no valid entry raises a page fault: the OS handler (Exceptions) either fetches the page from disk and retries the instruction, grows the mapping (stack, heap), or kills the process (segfault). Restarting faulted instructions is why precise exceptions exist.

The TLB

A page-table walk costs 2-4 memory accesses; doing it per load would be ruinous. The TLB (translation lookaside buffer) caches PTEs: 64-128 entries fully or highly associative for L1, ~1-2K entries in L2 TLB, reaching ~99%+ hit rates. TLB reach = entries × page size (128 × 4 KiB = 512 KiB), the reason huge pages help big-data workloads. Misses trigger the hardware walker (x86, RISC-V) or a software handler (old MIPS). Context switches either flush the TLB or tag entries with an ASID.

Caches Meet Translation

Where does the cache sit relative to translation?

  • PIPT (physically indexed, physically tagged): translate first, then look up. Simple, but adds TLB latency to every L1 hit. Used for L2/L3.
  • VIVT: fast but broken by homonyms (same VA, different PA per process) and synonyms (different VAs, same PA); requires flushes.
  • VIPT: index with page-offset bits (untranslated), fetch tags in parallel with the TLB, compare physical tags:

The constraint: index + offset must fit in the page offset, i.e. cache size ≤ page size × associativity (4 KiB × 8 = 32 KiB, the classic L1 size). VIPT gets PIPT correctness at VIVT speed, which is why the worked example above has exactly 64 sets.

Multicore hierarchy notes: private L1/L2 per core with a shared LLC is standard; inclusive LLCs duplicate all inner contents (wasteful, but the LLC can filter coherence traffic), exclusive maximize capacity, non-inclusive split the difference. Coherence itself is Multicore Cache Coherence.
