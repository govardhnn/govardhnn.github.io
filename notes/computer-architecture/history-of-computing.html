History of Computing

Computer architecture connects a software contract to a physical implementation. These milestones explain the design choices used throughout the notes.

From Machines to Stored Programs

Babbage’s Analytical Engine proposed arithmetic, storage, and conditional control. Early electronic computers made computation fast but often required external programming. Stored programs put instructions in addressable memory, allowing loaders, compilers, and programs that generate code. The Manchester Baby demonstrated electronic stored-program execution in 1948.

Memory Organization

Organization Instruction/data paths Tradeoff
von Neumann shared memory organization flexible code/data storage; shared resources can contend
Harvard separate instruction and data memories independent access; separate address/storage rules
modified Harvard split instruction/data caches over unified main memory parallel common-case access with a unified address space

Stored-program execution does not require a single physical port. Bandwidth depends on the implementation; coherence and instruction-cache synchronization matter when software modifies code.

ISA and Implementation Separate

IBM System/360 made a compatible ISA across a broad product family central to commercial computing. Implementations could use different datapaths and control while preserving program behavior. Instruction Set Architecture defines that contract; Simple Instruction Pipeline shows how hardware implements it.

Microprogramming sequences datapath control from a control store. Hardwired logic and microcode can coexist. RISC designs emphasized regular encodings, load/store operations, and compiler-friendly registers; CISC implementations often decode complex instructions into internal operations. Neither label alone predicts execution time.

Scaling and Parallelism

Moore’s law describes a historical component-count trend. Dennard scaling described shrinking dimensions and voltage together to improve speed without increasing power density; voltage scaling eventually stopped keeping pace.

Limit Architectural response Remaining cost
power and energy gating, DVFS, specialized units wake-up, voltage floors, reduced generality
limited instruction parallelism prediction, OOO execution, wider issue dependencies, recovery, wiring
memory latency/bandwidth caches, prefetch, concurrent requests locality, contention, energy

Multicore exploits thread parallelism; SIMD and accelerators exploit data parallelism. Flynn's Taxonomy compares them. Evaluate their benefits with execution time, Amdahl’s law, and representative workloads in Benchmarking.
