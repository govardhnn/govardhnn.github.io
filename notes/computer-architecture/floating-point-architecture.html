Floating Point Architecture

Fixed-point (integer) arithmetic has fixed range and absolute precision; science needs 10−3010^{-30} and 103010^{30} in the same expression. Floating point is binary scientific notation with a hardware contract: IEEE 754 (1985, revised 2008/2019) fixed the formats, rounding, and exceptional behavior, so the same program computes the same answers on every machine. Before it, every vendor’s FP differed and numerical code was unportable.

A normalized binary float:

x=(−1)s×1.f×2e−biasx = (-1)^s \times 1.f \times 2^{e - \text{bias}}

The leading 1 of a normalized significand is not stored (the hidden bit), buying one free bit of precision. The exponent is stored biased (unsigned ee = true exponent + bias) so floats sort like integers.

Formats

Format Bits (s/e/f) Bias Range Precision
binary16 (FP16) 1/5/10 15 ±6.5×104\pm 6.5 \times 10^4 ~3.3 digits
bfloat16 1/8/7 127 ±3.4×1038\pm 3.4 \times 10^{38} ~2.4 digits
binary32 (float) 1/8/23 127 ±3.4×1038\pm 3.4 \times 10^{38} ~7.2 digits
binary64 (double) 1/11/52 1023 ±1.8×10308\pm 1.8 \times 10^{308} ~15.9 digits
FP8 E4M3 / E5M2 1/4/3, 1/5/2 7 / 15 ±448\pm 448 / ±5.7×104\pm 5.7 \times 10^4 ~1 digit

bfloat16 is FP32 with the fraction truncated: same range, less precision, and conversion is a shift, which is why ML training adopted it; FP8 continues the trend for inference. Machine epsilon (gap between 1 and the next float) is 2−23≈1.2×10−72^{-23} \approx 1.2 \times 10^{-7} for FP32.

Special Values

The extreme exponent encodings are reserved:

exp field fraction Meaning
all 0s 0 ±0\pm 0 (signed zero)
all 0s ≠0\ne 0 subnormal: (−1)s×0.f×21−bias(-1)^s \times 0.f \times 2^{1-\text{bias}}
all 1s 0 ±∞\pm\infty
all 1s ≠0\ne 0 NaN (quiet if MSB of ff set, else signaling)

Subnormals give gradual underflow: without them the gap between 0 and the smallest normal number would exceed the gap between adjacent normals, and x != y could still make x - y == 0. Infinities propagate sensibly (1/0=∞1/0 = \infty); NaN results from invalid operations (0/00/0, −1\sqrt{-1}), propagates through arithmetic, and compares unequal to everything including itself (x != x is the NaN test). Hardware often executes subnormal arithmetic in slow microcode traps, a classic performance cliff.

Rounding

Most results need more bits than the format holds; IEEE requires the result to be the correctly rounded infinite-precision value. Modes: round-to-nearest-even (RNE, default), toward 00, toward +∞+\infty, toward −∞-\infty (the directed modes serve interval arithmetic).

RNE example, keeping 4 fraction bits: 1.00111000_21.0011\underline{1000}_2 is exactly halfway between 1.00111.0011 and 1.01001.0100, so the tie goes to the even LSB: 1.01001.0100. But 1.00101000_21.0010\underline{1000}_2, also a tie, rounds to 1.00101.0010 (already even). Ties-to-even prevents systematic drift in long computations.

Hardware keeps three extra bits through the datapath to round correctly after normalization: guard and round (the next two bits) and sticky (OR of everything below), enough to distinguish exactly-half from above/below half.

Exceptions: invalid, divide-by-zero, overflow, underflow, inexact. Default behavior is to deliver a well-defined result (∞\infty, NaN, rounded value) and set a sticky flag (RISC-V: in fcsr, read with frflags); trapping is optional. Code polls flags rather than fielding traps.

FP Addition and Multiplication Hardware

Addition is the hard one, because operands must be aligned first:

Worked: 1.1002×23+1.0102×211.100_2 \times 2^3 + 1.010_2 \times 2^1 with 3 fraction bits. Align: 1.010×21=0.01010×231.010 \times 2^1 = 0.01010 \times 2^3. Add: 1.100+0.01010=1.110101.100 + 0.01010 = 1.11010, already normalized. Round: the discarded bits are guard=1, round=0, sticky=0, an exact tie; the LSB of 1.1101.110 is even, so the result stays 1.110×231.110 \times 2^3. Effective subtraction of close values can cancel leading bits, requiring a big left shift found by a leading-zero counter.

Multiplication is structurally simpler: add exponents (subtract one bias), multiply significands with the integer multiplier array from Combinational Circuits, normalize (at most one position), round. Division and square root use iterative (SRT) or Newton-Raphson methods.

These stages make FP add/mul naturally 3-5 cycle pipelined units, one result per cycle; long-latency FP units are a main motivation for Out of Order Execution and Register Renaming.

FMA (fused multiply-add) computes a×b+ca \times b + c with a single rounding at the end: one instruction, better accuracy (no intermediate rounding), and it is the workhorse of dot products, matrix multiply, and every ML accelerator’s FLOPS claim.

Numerical Behavior

FP arithmetic is commutative but not associative: (x+y)+z≠x+(y+z)(x + y) + z \ne x + (y + z) in general. With FP32, (108+1)−108=0(10^8 + 1) - 10^8 = 0 (the 1 is below the precision of 10810^8) but (108−108)+1=1(10^8 - 10^8) + 1 = 1. Consequences: compilers cannot reorder FP without permission (-ffast-math), and parallel reductions get run-dependent answers.

Catastrophic cancellation: subtracting nearly equal values leaves only noise bits, e.g. the quadratic formula root −b+b2−4ac-b + \sqrt{b^2 - 4ac} when 4ac≪b24ac \ll b^2; rewrite as 2c/(−b−b2−4ac)2c / (-b - \sqrt{b^2-4ac}). Kahan summation carries a running compensation term to recover the bits ordinary summation drops.

RISC-V Floating Point

The F (single) and D (double) extensions of the RISC-V ISA add a separate register file f0-f31 (no hidden flags or stack, unlike x87):

  • Loads/stores flw/fld/fsw/fsd; compute fadd.s, fmadd.d (FMA), fsqrt.s, etc., each with an optional static rounding mode or the dynamic one in fcsr.
  • With D enabled, a single in an f register is NaN-boxed: stored in the low 32 bits with all-1s upper bits, so stale wide reads are visibly NaN.
  • fclass returns a one-hot classification (subnormal, zero, inf, NaN kinds), letting software test specials without raising flags.
  • Conversions fcvt.* cover int/float in both directions with explicit rounding.
