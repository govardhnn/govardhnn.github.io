Floating Point Architecture

Floating point represents values with a sign, significand, and exponent. IEEE 754 defines standard formats and arithmetic behavior; reproducibility also depends on operation order, rounding, compiler transformations, and handling of exceptional values.

A normalized binary float:

x=(−1)s×1.f×2e−biasx = (-1)^s \times 1.f \times 2^{e - \text{bias}}

The leading 1 of a normalized significand is not stored (the hidden bit), buying one free bit of precision. The exponent is stored biased (unsigned ee = true exponent + bias) which simplifies exponent comparison. Positive finite encodings sort by unsigned magnitude; signed values and NaNs need special handling.

bfloat16 shares FP32’s exponent width but has fewer fraction bits; conversion usually rounds rather than simply truncating. BF16 and FP8 variants are not all IEEE binary interchange formats; FP8 names require an exact variant definition. Machine epsilon (gap between 1 and the next float) is 2−23≈1.2×10−72^{-23} \approx 1.2 \times 10^{-7} for FP32.

Special Values

For IEEE binary16/32/64 (the FP8 variants above need their own rules):

exp field fraction Meaning
all 0s 0 ±0\pm 0 (signed zero)
all 0s ≠0\ne 0 subnormal: (−1)s×0.f×21−bias(-1)^s \times 0.f \times 2^{1-\text{bias}}
all 1s 0 ±∞\pm\infty
all 1s ≠0\ne 0 NaN (quiet if MSB of ff set, else signaling)

Subnormals fill the gap between zero and the smallest normal value with constant spacing. Finite nonzero division by zero returns signed infinity under default handling; invalid operations such as 0/0 produce NaN. NaNs compare unordered (x != x is true). Subnormal performance and flush-to-zero modes depend on the implementation.

Rounding

IEEE basic arithmetic operations must deliver the correctly rounded exact result in the specified format; this does not promise correct rounding for every library function. Common modes are round-to-nearest-even (RNE), toward 00, toward +∞+\infty, and toward −∞-\infty. RISC-V also supports round-to-nearest, ties to maximum magnitude (RMM).

RNE example, keeping 4 fraction bits: 1.00111000_21.0011\underline{1000}_2 is exactly halfway between 1.00111.0011 and 1.01001.0100, so the tie goes to the even LSB: 1.01001.0100. But 1.00101000_21.0010\underline{1000}_2, also a tie, rounds to 1.00101.0010 (already even). Ties-to-even prevents systematic drift in long computations.

Hardware keeps three extra bits through the datapath to round correctly after normalization: guard and round (the next two bits) and sticky (OR of everything below), enough to distinguish exactly-half from above/below half.

Exceptions: invalid, divide-by-zero, overflow, underflow, inexact. Default handling returns a specified result and sets sticky flags. RISC-V F/D expose flags through fcsr and do not define traps for these FP exceptions.

FP Addition and Multiplication Hardware

Addition is the hard one, because operands must be aligned first:

Worked with 3 fraction bits: 1.1002×23+1.0102×21=(1.100002+0.010102)×23=1.110102×23.1.100_2\times2^3+1.010_2\times2^1 =(1.10000_2+0.01010_2)\times2^3 =1.11010_2\times2^3. The exact sum is 14.514.5. Keeping 3 fraction bits gives 1.11021.110_2 with discarded 10: a tie. Its retained LSB is even, so RNE returns 1.1102×23=141.110_2\times2^3=14. Subtraction may require a left shift after cancellation.

Multiplication is structurally simpler: add exponents (subtract one bias), multiply significands with the integer multiplier array from Combinational Circuits, normalize (at most one right shift for normal input significands), then round; subnormals need additional handling. Division and square root use iterative (SRT) or Newton-Raphson methods.

These stages make FP add/mul naturally 3-5 cycle pipelined units, one result per cycle; long-latency FP units are a main motivation for Out of Order Execution and Register Renaming.

FMA (fused multiply-add) computes a×b+ca \times b + c with a single rounding at the end: one instruction, better accuracy (no intermediate rounding), and it is the workhorse of dot products, matrix multiply, and every ML accelerator’s FLOPS claim.

Numerical Behavior

Finite FP addition and multiplication are generally commutative but not associative; NaN payload handling can add exceptions: (x+y)+z≠x+(y+z)(x + y) + z \ne x + (y + z) in general. With FP32, (108+1)−108=0(10^8 + 1) - 10^8 = 0 (the 1 is below the precision of 10810^8) but (108−108)+1=1(10^8 - 10^8) + 1 = 1. Consequences: compilers cannot reorder FP without permission (-ffast-math), and changing a parallel reduction tree can change its answer.

Cancellation exposes errors already present in nearly equal operands; the subtraction itself can be exact. For the root (−b+b2−4ac)/(2a)(-b+\sqrt{b^2-4ac})/(2a) when b>0b>0 and 4ac≪b24ac\ll b^2, use the equivalent 2c/(−b−b2−4ac)2c/(-b-\sqrt{b^2-4ac}) to avoid the unstable numerator. Kahan summation tracks a compensation term to reduce accumulation error.

RISC-V Floating Point

The F (single) and D (double) extensions use f0-f31 and the fcsr rounding-mode/exception-flag register:

  • Loads/stores flw/fld/fsw/fsd; compute fadd.s, fmadd.d (FMA), fsqrt.s, etc., each with an optional static rounding mode or the dynamic one in fcsr.
  • With D enabled, a single in an f register is NaN-boxed: stored in the low 32 bits with all-1s upper bits, so stale wide reads are visibly NaN.
  • fclass returns a one-hot classification (subnormal, zero, inf, NaN kinds), letting software test specials without raising flags.
  • Conversions fcvt.* cover int/float in both directions with explicit rounding.
