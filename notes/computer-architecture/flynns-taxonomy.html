Flynn’s Taxonomy

Flynn (1966) classified machines by how many instruction streams and data streams they process at once. It remains the standard map of parallel hardware because it separates the two independent ways to scale beyond one instruction at a time: replicate the data an instruction touches, or replicate the instruction streams themselves.

Class Instruction streams Data streams Reality
SISD 1 1 classic uniprocessor, including superscalar (still one architectural stream)
SIMD 1 many vector machines, AVX, GPUs
MISD many 1 rare: systolic arrays (arguably), triple-modular redundancy
MIMD many many multicore, servers, clusters

Software-level refinements: SPMD (one program, many data partitions, an MIMD programming style: MPI, OpenMP) and SIMT (SIMD hardware presented as scalar threads: GPUs).

SIMD: One Instruction, Many Data

Data-level parallelism (DLP) is cheaper than instruction-level parallelism per operation: one fetch, one decode, one dependency check drive nn ALUs, amortizing exactly the frontend and control energy that limits superscalar width.

Vector processors (Cray-1, 1976; RISC-V V today) make DLP architectural:

  • Vector registers hold whole arrays (RVV: 32 registers of implementation-chosen length VLEN); vadd.vv v1, v2, v3 adds element-wise.
  • Lanes each own a slice of the register file and its ALUs; element ii never leaves lane imod⁡ni \bmod n: no inter-lane wiring, near-perfect scaling.
  • The vector length register handles arrays not divisible by the hardware length: vsetvli returns min⁡(remaining,VLMAX)\min(remaining, VLMAX) per iteration (strip mining), so one binary runs on any vector width.
  • Chaining forwards a vector result element-by-element into the next operation (the vector version of bypassing); masking predicates per-element for if bodies; gather/scatter indexes memory for sparse code; memory access is unit-stride, strided, or indexed.
# RISC-V V: c[i] = a[i] + b[i], any n
loop: vsetvli t0, a0, e64, m1   # t0 = min(n, VLMAX)
      vle64.v v1, (a1)          # load a slice
      vle64.v v2, (a2)
      vadd.vv v3, v1, v2
      vse64.v v3, (a3)          # store c slice
      sub a0, a0, t0            # n -= vl  (bump pointers omitted)
      bnez a0, loop

Packed-SIMD (SSE/AVX/NEON, and SWAR tricks in plain registers) fixes the vector length in the ISA encoding: 128 → 256 → 512 bits meant new instructions and recompiles each time, the pitfall true vector ISAs avoid. SIMT (GPUs) presents each lane as a “thread”; a warp of 32 executes one instruction, and divergent branches run both paths under masks, so control-heavy code wastes lanes.

A real RVV machine: Saturn

Berkeley’s Saturn is an open-source RVV 1.0 vector unit that attaches to an in-order scalar core, and its numbers make the vector story concrete. The evaluated build holds 512-bit vector registers over a 256-bit datapath; the register file is banked and striped so lanes read without conflict; a scoreboard tracks readiness per element group, delivering full chaining with zero dead time; and three independent sequencers (load, store, arithmetic) crack each vector instruction into micro-ops just 3 cycles from dispatch to writeback. In 16 nm it reaches 800 MHz in 0.41 mm² at ~121 SGFLOPS/W: DLP’s energy advantage, measured.

MIMD: Many Streams

Independent processors, each with its own PC, over a shared or distributed memory:

  • Shared memory (multicore): cores communicate through loads/stores; hardware must then answer what happens when they share data, which is Multicore Cache Coherence and the Memory Model.
  • Message passing (clusters, supercomputers): explicit sends/receives; scales past any coherent domain.

Multithreading is MIMD inside one core: coarse-grain (switch on stall), fine-grain (rotate every cycle: barrel processors), and SMT (issue from several threads in one cycle). What must be replicated per thread is only architectural state (PC, registers, CSRs); pipelines, caches, and predictors are shared. The issue-slot mechanics, costs, and the waste-filling picture are in Advanced Superscalar Architectures.

VLIW: The Compiler Alternative

A VLIW (very long instruction word) machine fetches one wide instruction containing several operation slots that execute in lockstep; the compiler finds the parallelism, schedules around latencies, and guarantees independence. The hardware needs no dependence checks, no rename, no issue queue: near-superscalar throughput at in-order cost.

Why Itanium (EPIC, 2001) still lost the general-purpose war:

  • Static schedules cannot adapt to dynamic cache misses (Caches and Virtual Memory latencies vary 10-100x), so the compiler must assume the worst or stall.
  • Empty slots become NOPs: code bloat.
  • The schedule bakes in one machine’s latencies, resurrecting the delay-slot mistake at scale.

Where latencies are static (DSPs, embedded media: TI C6x, Hexagon), VLIW thrives, and GPUs + compilers took the “smart compiler, dumb lockstep hardware” crown that EPIC aimed for.

Choosing

Parallelism Exploited by Best when
ILP superscalar + OOO irregular, branchy, pointer code
DLP vector/SIMD/GPU loops over arrays; same op, much data
TLP multicore, SMT independent tasks, servers

Real machines stack all three: a modern chip is MIMD over cores, each core superscalar (ILP) with vector units (DLP) and SMT (TLP), which is why Flynn’s clean quadrants blur in practice but the vocabulary survives.
